# V2.1.1 — Gold-Trained Tagger (training-only pipeline)

**Date:** 2026-06-14 · **Condensed:** 2026-07-29. V2.1.1 = a **full training run** on the gold / gold-augmented corpus (corrected Anima promoted into the data-limited main pool) to move decision boundaries — shrink off-diagonal confusions (`long_hair → absurdly_long_hair` over-fire; `aqua ↔ blue ↔ green`).
The cleaning pipeline = todos/janitor-cleaning-model-plan.md; the moved-out research is preserved in .research/_wf5_v2.1.1_verification.md.

## 0. IS / IS NOT

**IS:** a full training run on gold + gold-augmented data, producing the next checkpoint with cleaner boundaries on the noisy axes; gated by a held-out clean/gold eval slice + off-diagonal metric (§3, §4) — noisy-val F1 cannot see the over-fire.

**IS NOT:**
- ❌ Data-cleaning / label-correction or a review/suggestion UI — that is the cleaning pipeline (janitor plan).
- ❌ A frozen-backbone head-only (DFR) refit — this is a *full* run.
- ❌ A fine-tune of the biased V2 checkpoint on the small gold set — the documented "trap" (Kumar et al. 2022, arXiv:2202.10054). See §5, §7.

**Diagonal blind spot** (*don't let the tagger's own probability decide its own labels are wrong*, golden_set_plan §2.2/§8) holds by construction: V2.1.1 only trains; wrongness is decided upstream (external anchor + human, janitor plan). V2.1.1 consumes cleaned output, never certifies it.

## 1. Data flow

```
[cleaning pipeline (janitor plan)]          [V2.1.1 — this pipeline]
 raw booru + Anima gold                     main pool (data-limited)
   │  external-anchor cleaning                     ▲
   │  + human confirm/reject                        │  merge corrected Anima
   ▼                                                │  (fills starved cells)
 corrected labels ──────────────────────────────────┘
                                                     │
                          ┌──────────────────────────┴───────────┐
                          │  HOLD OUT a disjoint clean/gold slice │  (never trained on)
                          ▼                                       ▼
                    TRAIN (full run) ───► checkpoint ───► EVAL on held-out slice
                                                          (off-diagonal metric, §4)
```

**Non-negotiables baked into the flow:**
1. **Hold out a disjoint clean slice BEFORE training.** Most corrected Anima is promoted into training, but a fixed slice must stay sealed for eval — otherwise there is no yardstick and V2.1.1 is unfalsifiable (this was V1's exact failure: model selection on noisy `val/f1_macro`).
2. **Watch the synthetic:real ratio.** The gold is Anima (ComfyUI) output; the deployment domain is real booru art. Promoting too much synthetic into training installs a synthetic-domain bias. Quantify the ratio before committing (§7).
3. **Prior-correct before trusting the operating point.** The gold is boundary-**oversampled** ≠ deployment prior; correct per-tag thresholds or you swap one directional bias for the opposite (§6).

## 2. The boundary problem

- `absurdly_long_hair`: only **n=143** positives (chain `absurdly ⇒ very_long ⇒ long` at 0.0% violation in-data); independent sigmoids with zero rank coupling → the detector latches onto generic "very long hair" features.
- Gold training supplies many clean rare positives + clean sibling negatives — a genuine strength for this defect.
- But it softens, not enforces, `P(absurdly) ≤ P(very_long) ≤ P(long)`; the ordinal head is deferred (§5 P2).
- A coherence constraint (C-HMCNN, arXiv:2010.10151) is rejected: data is already coherent, and it raises the parent — it cannot lower an over-confident child.
- Full audit + reasoning: _wf5_v2.1.1_verification.md §3.

## 5. Training mechanics & guardrails  🔴

- [ ] **Pick the training regime (§7).** Default: from scratch (or continue) on the FULL augmented corpus, *not* fine-tune-on-gold — Kumar 2022: feature distortion "even with an infinitesimally small learning rate"; low LR does not make it safe.
- [ ] **Rare-class handling.** If promoted gold doesn't balance rare cells: decoupled classifier rebalancing (cRT, Kang 2020, arXiv:1910.09217) and/or logit adjustment (Menon 2021, arXiv:2007.07314) — both config-only compatible; keep ASL `gamma_neg`/`gamma_pos` config-driven.
- [ ] **Fix the re-binarize snapshot BEFORE any soft/ordinal label.** loss_functions.py:269 (`targets_for_focal = targets`) snapshots targets before smoothing; a soft target (e.g. 0.7) would leak into *both* focal weight masks. Correct for {0,1}; latent bug once soft labels arrive.
- [ ] **No-regression gate.** Compare the ~19,250 non-targeted tags' clean-slice mAP vs the prior checkpoint — a full train *can* regress them; a real gate, not a formality.

### P2 — ordinal structure (DEFERRED — the real cure for the hair-length axis)  🟡
- CORN/CORAL sub-head over length/breast groups (CORAL arXiv:1901.07884; CORN arXiv:2111.08851) enforcing `P(≥long) ≥ P(≥very_long) ≥ P(≥absurdly)`.
- Soft-label path (SORD, Diaz & Marathe 2019 CVPR) — **requires the loss_functions.py:269 fix first**.
- Source ordinal gold from **real human-rated booru**, not only synthetic (golden_set_collection_targets §8).
- Recommendation: keep ordinal machinery out of V2.1.1; cleaner data this round, structural head later.

## 6. Prior-shift / threshold correction  🟡

Gold is boundary-oversampled ≠ deployment booru prior; uncorrected, the model over-fires oversampled classes at fixed threshold (golden_set_plan §2.3). **Code reality:** per-tag threshold **loader** exists (onnx_infer.py:324-338 — now accepts both `thresholds.json` and `pr_thresholds.json`) but **no producer** derives prior-shift offsets; tools/find_pr_threshold.py calibrates P=R on the *biased* val split.

**Tasks:**
- [ ] Emit per-tag **prior-shift offsets** into `thresholds.json`. Deployment prior is **known**, so use the **closed-form analytic offset** `−log P_gold(y) + log P_booru(y)` (Saerens 2002; Menon 2021) — **not BBSE** (Lipton 2018 estimates an *unknown* prior; error blows up on exactly the rare cells). Keep a tunable temperature on the clean slice (synthetic≠real ⇒ partial label-shift).
- [ ] For one-vs-all sigmoids the offset is exactly a per-tag threshold shift — raising `absurdly_long_hair`'s threshold toward its ~0.3% prior directly suppresses the residual over-suggestion (symptom relief, not a cure).

If cleaning runs first, the **janitor plan §4.2 ρ-corrected prior supersedes the naive corpus prior**.

**Done when:** the operating point matches the real-booru prior, not the gold prior.

## 10. Acceptance criteria
- **Yardstick exists:** off-diagonal confusion is measurable on a sealed slice nothing trained on (§3, §4).
- **Targeted boundaries improved:** `long→absurdly` fire-rate and the color confusion cells shrink on the sealed slice vs the prior checkpoint.
- **No broad regression:** the ~19,250 non-targeted tags' clean-slice mAP is not worse than the prior checkpoint.
- **Prior-corrected:** operating point matches the real-booru prior, not the gold prior (§6).
- **Domain honesty:** the synthetic:real training ratio is recorded and within an acceptable bound (§7).
