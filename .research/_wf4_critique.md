**1. SILENT-FAILURE configs — how the user gets fooled**

1a. **Evaluating on dirty-corpus val (the master trap).** Every metric in `train_direct.py`/`validation_loop.py` is computed against the 6M dirty GT. The dirty val *encodes the down-bias as ground truth*. A fine-tune that preserves the bias scores BETTER on dirty val than one that fixes it (Wang ICCV'23 persistence: in-distribution metrics stay healthy while bias persists). If the user watches val loss / val mAP, the signal is inverted — debiasing looks like regression. Decisive: the ONLY admissible metric is a held-out, group-balanced GOLD split. Nothing in the repo computes this today; it must be built or the run is uninterpretable.

1b. **Balanced sampler with gamma_neg=7 unchanged (silent no-op on bias).** This is the most likely config the user actually lands in, because it's "just add a sampler" with zero loss edits. The balanced batch shows medium/very_long positives, but `gamma_neg=7` zeroes their recovery gradient (`loss_functions.py:308-315`: confident-negative shift drives `neg_weights→0`, and the positive side can't lift because the stale log-prior bias keeps the threshold high). Training loss drops (the head trivially fits the easy majority), gold-train accuracy ticks up a little, and the boundary cells barely move. Looks like it worked; didn't. Fix requires gamma_neg→1-2 AND bias recalibration, not sampling alone.

1c. **LP-FT / partial-unfreeze with the cosine scheduler (silent full-FT).** If the user extends `get_parameter_groups` for discriminative LRs, the layer-wise path emits `lr_scale` multipliers (`:2781/2788`) and the LR logging/scheduler reads `param_groups[0]['lr']` (`:1842,2283`). `CosineAnnealingWarmupRestarts` rescales a single `max_lr`; with no per-group `base_lrs`, the backbone group gets lifted to the head's max_lr. The user thinks they're running a 1e-5 backbone; they're running 1e-3 across 192M params on 1.5-3K images = the trap, silently. The log shows one LR and looks fine.

1d. **Full-head refit without column-masking (silent 19K regression).** Refitting the whole `tag_head` on hair-only gold: gold images carry true positives for many co-occurring tags but the gold labels only the 6 hair tags, so every other true tag becomes a confident negative under gamma_neg=7 and gets actively suppressed (`neg_weights` on `:315`). Gold hair metrics improve; the other ~19K columns rot. The user never looks at non-hair tags, so it's invisible without a per-tag regression tripwire on a general slice.

1e. **Soft-label corruption (silent, physical).** If the user adopts ordinal soft labels (the right encoding for the scale) without fixing `:269`, fractional targets flow into `targets_for_focal` and mis-gate the focal masks at `:314-315` — a 0.3 target becomes 0.3 positive weight, not a clamped {0,1} gate. Gradients are wrong, not merely smoothed; loss still decreases. The ordinal signal you're trying to teach is exactly what's corrupted.

1f. **Re-running `initialize_tag_head_bias` with the dirty `tag_frequencies` (silent re-injection).** This re-writes the down-tilted log-prior (`:88`) and re-creates the bias even under a perfectly balanced sampler. Trivially easy to do by copy-pasting the existing init call.

**2. FEATURE-CEILING reality — likelihood and the kill-gate**

2a. **Likelihood the ceiling bites: HIGH for the hardest cells, partial elsewhere.** v1 was trained on GT where medium collapsed to ~5.8% and 76% of long_hair images are long-only. The supervision signal that would have forced the CLS geometry to separate long↔very_long and to carve out medium was itself degraded — so it is genuinely likely v1's frozen features under-separate exactly the boundary you care about (LaBonte NeurIPS'23: last-layer retraining only works if the core feature was learned). But it is NOT all-or-nothing: very_short/short/absurdly_long have stronger visual signatures and probably survive in features; the medium-vs-long and long-vs-very_long boundaries are where collapse is most probable. Expect DFR to recover the easy bins and stall on the two hard cells.

2b. **The frozen-v1 probe is the right gate, but only if specified correctly.** It is the cheap, correct experiment because the CLS vector IS the head input (`:665-669`) — zero abstraction. But it is only valid with: (i) image-level (not tag-level) stratified split; (ii) group-balanced/medium-oversampled probe train set; (iii) a rank-consistent ordinal probe (CORN/CORAL), not nominal BCE; (iv) ALL metrics on a held-out GOLD split; (v) the SAME probe on a frozen DINOv2 backbone as the control. Without the DINOv2 control you cannot distinguish "feature absent in v1" from "task is just hard / gold too small" — the control is what converts the result into a decision.

2c. **The result that KILLS v1-FT entirely:** v1-frozen probe collapses long↔very_long (and fails to lift medium) **while DINOv2-frozen probe separates them on the same images**. That gap is the quantified ceiling and it is dispositive — it proves the feature was never encoded, so no linear refit and no LP-FT can recover it (re-learning a feature direction into 18 layers from 1.5-3K images is hopeless + harmful), and the DINOv2 specialist is the only path. Conversely, if v1-frozen ≈ DINOv2-frozen on the boundary, DFR is cheap and viable. Run this BEFORE any fine-tune compute.

**3. MULTI-LABEL FORGETTING — is the guard sufficient?**

3a. **Last-layer-only (DFR) sidesteps backbone forgetting CLEANLY and completely.** Backbone frozen ⇒ the 192M feature params are bit-identical ⇒ the other 19K tags' *features* cannot move. This is a structural guarantee, not a regularizer. The "fine-tuning the shared backbone inevitably disturbs 19K tags" problem simply does not arise in DFR because the backbone is never touched. That is DFR's decisive safety win.

3b. **But head-only does NOT automatically protect the other 19K head COLUMNS.** The single `nn.Linear` is shared: weight rows for all ~19K tags live in `tag_head.weight`. Refitting the head on hair-only gold drags every column via the gamma_neg=7 hard-negative channel (§1d). The guard must be structural: **column-mask** (a backward hook zeroing gradient on all non-hair rows of `tag_head.weight/bias`) OR **`ignore_indices`** masking the loss to the 6 hair columns (the keep-mask path exists, `loss_functions.py:252-263` — verified; but it builds a ~19K-long ignore list, so confirm it's built once and cached, not per-step). Column-mask + frozen backbone ⇒ the other 19K tags are *mathematically frozen*, end to end. That combination IS sufficient.

3c. **Distillation/L2-SP are the WEAKER guards and only needed if you refuse to mask.** KD (frozen-v1 sigmoids as soft targets on non-hair columns) and L2-SP (anchor non-hair weights to v1) are regularizers — they *reduce* drift, they don't *prevent* it, and they reintroduce tuning surface (anchor strength, replay ratio). For this goal they're dominated by column-mask, which is a hard zero. Recommended config is mask + freeze; skip KD/L2-SP for the minimal correct build.

3d. **Verdict on the question as posed:** DFR (last-layer-only) sidesteps the *backbone* forgetting trap cleanly; it does NOT by itself sidestep the *shared-head-column* trap — that needs the explicit column-mask/ignore_indices guard, which is available and sufficient. Any config that unfreezes backbone reintroduces the inevitable-disturbance problem and should be rejected here.

**4. Does v1-gold-FT serve the REAL goal (clean the poison GT)?**

4. **No — it serves the symptom, not the disease, and conflating them is the central distraction.** v1-gold-FT changes what the *deployed model suggests*; it does not rewrite a single on-disk GT label. The real goal is cleaning the poisoned 6M GT so a future model isn't trained on the down-bias. v1 is structurally disqualified as the *cleaner/detector* by circularity: it memorized the exact convention you want to surface (it fires long_hair on 3.12M imgs with ~0 hair-length false-negatives — it literally cannot believe the GT length is wrong). Using v1 to find v1's bad labels re-introduces the circularity the gold set exists to break (Xia/Yao non-identifiability: instance-dependent noise is unrecoverable from the noisy corpus alone, and v1's features ARE the noisy corpus). **Genuine value of v1-gold-FT:** a cheap, safe, reversible, ship-this-week recalibration of the live suggestion engine — better medium/very_long suggestions in the labeling UI, which can *assist* a human-in-the-loop cleaning pass and reduce annotator reflexive-long clicks. **The distraction:** treating an improved confusion matrix on gold as evidence the corpus is cleaner, or as a substitute for the DINOv2 detector. It is neither. The detector (clean) and v2-from-scratch-on-repaired-GT (raise the ceiling) are the cure; DFR-on-gold is an interim patch on the symptom.

**5. THE HONEST CALL**

**AS-A-CHEAP-COMPLEMENT — conditional, not unconditional.**

It is NOT worth doing as the primary tool (that's the DINOv2 detector + v2-on-clean-GT) and it is NOT a no-brainer. It IS worth doing as a cheap complement — but only as DFR (frozen backbone + hair-only column-mask + balanced sampler + gamma_neg→1-2 + bias re-derived from balanced gold priors, evaluated on a held-out balanced gold split), and only if it passes the gate.

**The single deciding condition:** the frozen-v1 probe (§2b) must separate long↔very_long and lift medium to within a small margin of the frozen-DINOv2 control on a held-out gold split. 
- If YES → DFR is a cheap, safe, ship-this-week patch for the live suggestion engine; do it *in parallel with*, never *instead of*, the DINOv2 detector. 
- If NO (v1 collapses while DINOv2 separates) → v1-gold-FT is dead on arrival at any point on the freeze-spectrum; skip it entirely and put all effort into the DINOv2 specialist and v2. 

Run the probe first. It costs minutes and it is the one experiment that converts this from a judgment call into a decision. Full fine-tuning is off the table in every branch (maximal feature distortion per Kumar ICLR'22, severe 19K-tag forgetting amplified by gamma_neg=7, and the bias persists anyway per Wang ICCV'23 — it pays the most and buys the least).
